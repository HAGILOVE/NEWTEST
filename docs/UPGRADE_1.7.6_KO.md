# Aether EM 1.7.6 — 도킹 창 크기 조절, 뷰포트 내 도면 작성, "왜 안 보이는가"

새 폴더에 압축 해제 후 `SETUP_WINDOWS.cmd` → `START_WINDOWS.cmd` 실행.

1.7.5에서 보고된 네 가지 중 세 가지를 이번 버전에서 처리함. 나머지 하나(특정 프로젝트가 열렸는데 화면에 아무것도 안 나오는 건)는 원인을 특정할 수 있는 진단 기능을 넣었음 — 아래 4절 참조.

---

## 1. Message 창을 포함한 모든 도킹 창 크기 조절

Message Manager는 178 px 고정이었음. import 보고서 한 줄 반 높이임.

- `Message Manager / Progress / Scripting Console` 패널 **위쪽 경계**를 끌어서 높이 조절.
- **Project Manager**(왼쪽) 오른쪽 경계를 끌어서 폭 조절.
- **Properties** 패널 위쪽 경계를 끌어서 높이 조절.
- 경계를 **더블클릭**하면 기본값으로 복귀함.
- 탭 줄을 더블클릭하거나 우측 `▲` 버튼으로 패널을 탭만 남기고 접거나 화면의 62%까지 펼침.
- 크기는 브라우저에 저장되어 다음 실행 때 유지됨.

## 2. Box by points — 모달 창 없이 마우스로 그리고 좌표창에서 수정

이전 동작: 두 점을 클릭하면 **모달 대화상자가 모델 위를 덮고**, 방금 클릭한 좌표를 다시 입력하라고 요구했음. 그리는 대상이 대화상자에 가려졌음.

새 동작: 좌표가 뷰포트 **좌측 상단 패널**에 표시되고, 모달은 없음.

| 표시 항목 | 동작 |
| --- | --- |
| Cursor X/Y/Z | 마우스를 움직이는 동안 실시간 갱신(읽기 전용) |
| Corner 1 / Corner 2 (원통은 Centre / Rim) | 클릭하면 채워지고, **직접 수정 가능** |
| Size dX/dY/dZ | 두 점의 차이. 여기에 값을 넣으면 Corner 2가 따라 움직임 |
| Radius (원통) | 반지름을 직접 입력 가능 |
| Height | 마우스를 위아래로 움직이면 실시간 갱신, 직접 입력도 가능 |
| Name / Material / Snap | 그리는 도중에 지정 |

- 값을 입력하고 **Enter**를 누르면 그 단계를 클릭한 것과 동일하게 처리됨. 마지막 단계에서 Enter는 Create임.
- **Esc**는 전체 취소가 아니라 **한 점씩 되돌림**. 두 번째 점을 잘못 찍었다고 처음부터 다시 할 필요가 없음.
- 그리는 동안 모델 위에 **와이어프레임 미리보기**와 크기 라벨(가로 × 세로 × 높이)이 함께 표시됨.
- `S` 키로 스냅 on/off. 현재 스냅 간격이 패널에 표시됨.
- Box / Rectangle / Cylinder 모두 같은 방식임. Draw 메뉴의 숫자 입력 대화상자(Draw ▸ Box 등)는 그대로 남아 있음 — 치수를 이미 알고 있을 때 쓰는 경로임.

## 3. 상태 표시줄 좌표

마우스 위치의 X/Y/Z가 상태 표시줄에 항상 표시됨. 형상 위에서는 형상 표면의 점을, 빈 공간에서는 작업 평면상의 점을 읽음.

## 4. "불러왔는데 화면에 아무것도 안 나옴"

이 증상은 원인이 여러 가지인데 화면만 보고는 구분이 불가능했음. 그래서 원인을 객체 단위로 말해주는 기능을 넣었음.

**`View ▸ Display Diagnostics…`** (뷰포트 툴바의 체크 아이콘, Ribbon의 `View ▸ Why blank?`)

각 객체를 다음 중 하나로 분류하고 재료·투명도·치수와 함께 표로 보여줌.

| 상태 | 의미 |
| --- | --- |
| displayed | 정상적으로 그려짐 |
| no geometry | 프로젝트가 native(Parasolid) body로 저장하고 있어 이 커널이 읽지 못함. HFSS에서 STEP으로 export 후 Replace CAD Source |
| not drawable | 형상은 있으나 삼각형 분할 실패. 실패 사유가 함께 표시됨 |
| hidden | Properties에서 Visible이 꺼져 있음 |
| empty | 분할 결과 삼각형이 0개 |

그리고 **"그려지긴 했는데 안 보이는" 두 경우**를 명시적으로 지적함.

- 표시되는 body가 전부 투명도 0.8 이상인 경우 — air / vacuum / PML region이 정확히 이 상태임. 재료 투명도가 0.95면 화면이 거의 비어 보임. **이 경우 프로젝트를 열 때 Solid Display를 자동으로 켜고 상태 표시줄에 그 사실을 알림.**
- 가장 큰 body가 가장 작은 body의 200배를 넘는 경우 — 작은 부품이 확대 전까지 1픽셀 미만임.

**`View ▸ Solid Display`** (뷰포트 툴바에도 있음): 재료 투명도를 무시하고 모든 body를 불투명하게 그림. 언제든 다시 끌 수 있음.

또한 **삼각형 분할에 실패한 body는 이제 화면에서 사라지지 않고 bounding box 와이어로 표시**되고, 뷰포트 좌측 상단에 `N shown as extent box only`로 집계됨. 위치는 맞는 상자가 보이는 편이 아무것도 없는 것보다 낫다는 판단임.

뷰포트 좌측 상단 표시도 `그려진 개수 / 전체 개수`로 바뀌었음. 29개 중 17개만 그려졌다면 그 사실이 화면에 계속 보임.

**`View ▸ Fit Selection`** (`Ctrl+Shift+D`, 트리 우클릭의 `Zoom to Object`)도 추가함. Fit All은 radiation box 기준으로 맞추므로 그 안의 patch는 1픽셀 미만이 됨. 선택한 객체 기준으로 카메라를 맞추는 것이 실제로 필요한 동작임.

### 남은 한계 — aa_coil 건

말씀하신 `aa_coil` 프로젝트가 실제로 어느 경우인지는 **파일 없이는 특정할 수 없음**. 메시지 로그에 남은 것은 29개 중 12개가 Parasolid로 읽히지 않았다는 사실뿐이고, 나머지 17개가 (a) 정상적으로 그려졌으나 전부 투명한 region이었는지, (b) 분할에 실패했는지, (c) air box에 비해 너무 작았는지는 로그만으로 구분되지 않음.

위 진단 기능이 그 구분을 화면에서 바로 해 주지만, 근본 원인이 (b)라면 코드 수정이 더 필요함. `aa_coil.aedt`(또는 `.aedtz`)를 주면 실제 파일로 재현해서 고칠 수 있음.
