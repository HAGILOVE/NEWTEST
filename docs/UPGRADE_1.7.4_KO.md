# Aether EM 1.7.4 — 개별 엣지 선택과 대용량 STEP 표시 최적화

새 폴더에 압축 해제 후 SETUP_WINDOWS.cmd → START_WINDOWS.cmd 실행. 대형 STEP은 START_FAST_WINDOWS.cmd로 실행할 수 있음.

## 개별 Edge 선택

1.7.3에서 면의 둘레 전체를 선택한 것은 요구 해석 오류였음. 이번 버전은 CAD가 제공하는 개별 curve ID를 유지하여 두 CAD 꼭짓점 사이의 엣지를 선택함. 한 곡선이 여러 표시 선분으로 나뉘어도 같은 curve이면 함께 선택하며, 접선으로 이어진 별도 curve는 합치지 않음.

CAD 커널이 없는 기본 도형·DXF 참조선은 연결점에서 방향이 꺾이거나 분기되면 선택을 끊음. 사각형 네 변은 각각 선택됨. 같은 방향의 분할 선분은 하나의 변으로 연결함. 이 fallback은 20도 방향 변화 기준을 사용하는 근사 연결이므로 원본 CAD 위상과 항상 일치하지는 않음.

분할되지 않은 완전한 원은 그 자체가 하나의 닫힌 CAD edge일 수 있으므로 원주 전체 선택이 정상임. 원 위의 임의의 두 점 사이 구간을 별도 edge로 선택하려면 원본 형상을 Split해야 함. 이번 버전은 임의의 두 클릭점으로 곡선을 분할하는 기능을 추가한 것은 아님.

## 대형 파일 성능 변경

- 조립체의 각 부품마다 전체 메시 노드를 다시 가져와 정렬·복사하던 처리를 파일당 한 번으로 공유함.
- 마우스 선택에 삼각형 BVH를 적용함. 레이와 교차하는 공간의 삼각형만 정밀 검사함. 원래 triangle/face 인덱스는 유지함.
- 일반 객체·점 호버에서 불필요한 전체 메시 face-highlight 갱신을 줄임.
- 불필요한 모든 삼각형 내부 선 대신 모델 경계선을 렌더링함. Wireframe은 모델 외곽선 표시이며 해석 메시 표시는 별도임.
- 큰 정점 인덱스를 지원하지 않는 WebGL 환경에서 16비트 인덱스 잘림 대신 펼친 선 버퍼를 사용함.
- 표시용 곡률 분할 기본값을 96→48로 줄임. Smooth normals는 유지함. FEM 해석 메시 설정은 변경하지 않음.
- START_FAST_WINDOWS.cmd는 표시용 곡률 분할을 32로 설정함. 곡선 실루엣·샘플 기반 측정의 정밀도와 속도 사이의 절충임.

고급 설정: AETHER_VIEW_CURVE_SEGMENTS 환경변수 16~128. 기본 48, 상세 표시 96. 서버 재시작 후 적용됨. 정밀 곡선 치수에는 표시 선분 근삿값 대신 원본 CAD 치수 확인이 필요함.

## 검증 및 남은 한계

전체 pytest 467개: 349개 통과, 118개 건너뜀, 실패/오류 0개. 이후 선택 가속 코드 정리 및 face-highlight 최적화에 대해서 관련 테스트를 재실행함. Python 컴파일·JavaScript 구문 검사 통과. 결과 XML 포함.

합성 22,500개 삼각형 장면에서 한 선택 레이의 후보를 15개로 줄였음. 가속 구조 생성은 측정 실행에서 약 50ms였으며 환경에 따라 달라짐. 여러 hit/miss/모서리 레이에 대해 기존 전수 검사와 동일한 선택 결과를 확인함. 이 수치는 실제 STEP 로딩 시간이나 전체 편집 속도의 개선율이 아님.

실제 느린 STEP 파일은 아직 제공되지 않아 파일별 로딩 시간·메모리·Windows FPS는 검증하지 못함. OCC 실행 및 실제 브라우저 렌더 테스트도 현재 환경 제한으로 완료하지 못함. 매우 큰 파일의 초기 CAD 파싱, 표시 메시 생성, JSON 전송 및 GPU 메모리 비용은 남아 있음. 따라서 어떤 용량도 즉시 편집 가능하다고 보장하지 않음. 계속 느리면 원본 STEP, 용량, 대략적인 부품 수, 로딩 시간과 RAM/GPU 정보로 추가 프로파일링해야 함.

기존 HFSS/PML 제한과 치수 보관 기능의 제한은 1.7.3 안내와 같음.
