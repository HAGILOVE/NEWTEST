## 1. Sweep Face Along Normal — 별도 객체가 생성됨 (버그 수정)

**원인**: `_build_face_op`이 `op` 값을 아예 쓰지 않았음. sweep이든 move든 같은 코드로 "swept volume을 본체에 fuse"만 하고 있었음. 두 명령이 문자 그대로 동일하게 동작했음.

**수정** — HFSS와 같은 의미로 분리함.

| 명령 | 동작 |
| --- | --- |
| **Sweep Face Along Normal** | 면을 법선 방향으로 sweep한 **부피를 새 객체로 생성**. 면이 속한 본체는 그대로 둠 |
| **Move Faces** | 면을 끌어서 본체를 키우거나(양수) 깎음(음수). 새 객체 없음 |

- 새 객체 이름은 대화상자에서 지정할 수 있고, 비우면 `<원본이름>_Sweep`이 됨.
- 새 객체는 원본 body의 재료를 물려받음. 이후 별도 재료·boundary·port를 지정할 수 있음 — 이 명령의 존재 이유임.
- 검증: 20×10×4 mm box의 윗면을 3 mm sweep → `Box1`은 z 0~4 mm 그대로, `Box1_Sweep`이 z 4~7 mm로 **새로 생성**됨.

## 2. Box by points — 방향 반전 (버그 수정)

**원인**: 높이 단계에서 커서 위치를 구하는 최근접점 계산의 **부호가 반대**였음.

직선 `P(t) = a + t·n` 과 광선 `Q(s) = o + s·d` 의 최근접 조건은

```
t = (n·w0 − (d·n)(d·w0)) / (1 − (d·n)²),   w0 = o − a
```

인데 코드가 `(d·n)(d·w0) − n·w0` 을 반환하고 있었음. 즉 항상 `−t`. 그래서 마우스를 올리면 아래로 자랐음.

## 3. 마우스 드래그로 여러 개 선택 (신규)

**Ctrl + 드래그**로 뷰포트에 사각형을 그리면, 현재 선택 모드(O/F/E/V)에 해당하는 것이 **사각형 안에 들어온 만큼 전부 선택**됨. 뷰포트 툴바의 상자 버튼으로도 무장할 수 있음(그 다음 한 번의 드래그가 선택이 됨).

| 모드 | 판정 기준 |
| --- | --- |
| Object | 객체의 삼각형 중심 표본이 사각형 안에 하나라도 들어오면 선택 |
| Face | 각 면의 자체 중심점 |
| Edge | 각 edge의 중점 |
| Point | 각 표시 정점 |

- **Shift를 함께 누르면 기존 선택에 추가**, 아니면 교체함.
- 정점을 여러 개 선택하면 개수 · 최대 이격 거리 · bounding box를 화면에 표시함. 두 개만 선택하면 기존처럼 두 점 사이 거리를 계산함.
- 실측: `total_aa.step` + `XY.dxf`를 올린 상태에서 전체 드래그 시 object 19개 / face 311개 / edge 5,100개가 한 번에 선택됨.

Shift+드래그와 가운데 버튼은 이전처럼 pan임. 회전은 그대로 좌클릭 드래그임.

## 4. 마우스로 방향을 정하고 수치를 입력해 이동 (신규)

**`Edit ▸ Move by Two Points…`** (`Ctrl+M`, 뷰포트 툴바의 이동 아이콘, 객체 우클릭 메뉴)

1. 객체를 선택함(다중 선택 가능).
2. 기준점을 클릭함.
3. 목적지를 클릭함 — 또는 패널에 값을 입력함.

패널에 표시·수정 가능한 항목:

| 항목 | 동작 |
| --- | --- |
| Cursor | 마우스 위치 실시간(읽기 전용) |
| From / To | 클릭하면 채워지고 직접 수정 가능 |
| Delta dX/dY/dZ | 이동량. 직접 입력 가능 |
| Distance | **방향은 유지한 채 거리만 변경** — 방향을 마우스로 정하고 거리를 타이핑하는 용도 |
| Copy | 원본을 남기고 복사본을 이동 |
| Snap | 격자 스냅 on/off (`S` 키) |

- 이동 중에는 선택 대상의 bounding box가 **이동 후 위치에 와이어프레임으로 미리 표시**되고, 이동 벡터와 거리가 화면에 라벨로 붙음.
- `Enter`는 적용, `Esc`는 한 단계 되돌림.
- 기존 `Arrange ▸ Move…` 대화상자는 그대로 남아 있음.

## 5. STEP / DXF import 속도

**원인 측정**(`total_aa.step`, 18 body, 전부 NURBS면):

| 단계 | 이전 |
| --- | --- |
| `inspect()` — 파일 읽기 1회 + 표면 메시 1회 | 약 4 s |
| `list_bodies()` — 파일 읽기 1회 + 표면 메시 1회 (같은 일을 반복) | 약 4 s |
| `view.geometry` — 파일 읽기 1회 + 표면 메시 1회 (또 반복) | 약 5 s |
| **합계** | **약 12.3 s** |

같은 파일을 **3번 읽고 3번 메시**하고 있었음.

**수정**

- `inspect`와 `list_bodies`를 하나의 세션으로 합침 → 읽기 1회, 메시 1회.
- 그 메시를 버리지 않고 **표시용 버퍼로 수확해서 캐시**함. 뷰포트가 원하는 것이 정확히 그 메시임.
- DXF도 마찬가지로, import 검증을 위해 만든 tessellation을 버리지 않고 캐시함.

| | 이전 | 1.7.8 |
| --- | --- | --- |
| `total_aa.step` import | 6.6 s | **5.3 s** |
| 그 뒤 화면 표시 | 5.7 s | **0.04 s** |
| **합계** | **12.3 s** | **5.3 s** |
| `XY.dxf` import + 표시 | 9.9 s | **6.5 s** |

남은 시간의 대부분은 OCC의 STEP 파싱과 NURBS 면 메시 자체임. 표시 메시는 더 이상 병목이 아님.

## 6. "modeler.importCad: no design is open" (버그 수정)

프로젝트를 닫은 상태(또는 아직 열지 않은 상태)에서 import·draw 명령이 `no design is open — use Project ▸ Insert Design`으로 거절됐음. 사용자가 할 일을 알려주는 게 아니라 수수께끼를 내는 동작이었음.

이제 **필요한 문서를 스스로 만들고 그 사실을 상태 표시줄에 알림**. 프로젝트가 아예 없으면 새 프로젝트를, 프로젝트는 있는데 디자인이 없으면 디자인을 만듦. Import CAD, Draw 대화상자, Draw by points 모두 해당함.

실측: 프로젝트를 닫은 상태에서 `total_aa.step` import → 8.1 s에 18개 객체 표시.

## 7. 그 밖의 수정

- **선택이 뒤늦은 응답에 의해 취소되던 문제.** 모든 RPC 응답이 전체 state를 실어 오는데, 응답이 도착했을 때 그보다 나중에 한 선택을 덮어쓰고 있었음. 재빌드 중에 객체를 클릭하면 선택이 사라지는 증상임. 선택에 epoch를 붙여 늦게 도착한 응답이 최신 선택을 되돌리지 못하게 함.
- 브라우저 탭을 응답 도중에 닫아도 서버가 죽지 않도록 함(BrokenPipe 처리).
- 문서를 교체할 때 blob 캐시를 전부 비우지 않고 소량만 남김. 전송 중이던 요청이 404로 실패해 재요청하던 것을 없앰.
